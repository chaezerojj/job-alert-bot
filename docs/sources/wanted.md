## 사전 조사 체크리스트 (사용자와 함께)

- [ ] 이용약관에서 자동 수집 관련 조항 확인 → 결과를 아래에 기록
- [ ] `https://www.wanted.co.kr/robots.txt` 확인 → 공고 목록·상세 경로가 허용되는지 기록
- [ ] 브라우저 개발자도구 Network 탭(Fetch/XHR 필터)에서 공고 **목록** 화면이 호출하는 JSON 요청 찾기
  - 요청 URL, 쿼리 파라미터(직군·경력·정렬·페이지), 응답 예시 1건을 기록
- [ ] 같은 방식으로 공고 **상세** 화면의 JSON 요청 찾기 (JD 본문·기술 스택이 있는지)
- [ ] 로그인 없이 접근 가능한지 확인
- [ ] 같은 요청을 GitHub Actions 환경에서도 시도 → 봇 차단 여부 기록

## 구현 방식 결정 기준

1. 약관·robots.txt상 허용되지 않음 → **수집하지 않음.** DECISIONS.md에 기록하고 사람인 단독으로 MVP 진행
2. 허용 + 내부 JSON 요청이 있음 → `fetch`로 JSON 호출 (Playwright 불필요, 가장 덜 깨짐)
3. 허용 + JSON을 못 찾음 → Playwright로 렌더링 후 DOM에서 추출
4. Actions에서만 차단됨 → 원티드는 사용자 PC에서 돌리는 방안 등을 사용자와 상의

## 변환 메모

- 상세 JSON에 JD 본문이 있으면 `Job.description`에 넣는다 (LLM 입력 시 앞 2,000자 정도로 자름)
- 기술 스택 태그가 있으면 `Job.techStack`에 넣는다
- 상세 요청은 공고 수만큼 늘어나므로, **1단계 규칙 필터를 통과한 공고만** 상세를 가져오는 것도 고려
