# 수집기 공통 규칙

> 새 사이트를 추가하거나 수집기를 고칠 때 이 문서를 먼저 읽는다.

## 인터페이스

모든 수집기는 같은 모양이다.

```ts
// src/collectors/<site>.ts
export async function collect<Site>(options: CollectOptions): Promise<Job[]>;

type CollectOptions = {
  keywords: string[];     // profile.yaml에서 옴
  maxItems: number;       // 사이트당 상한 (기본 100)
  signal?: AbortSignal;   // 전체 타임아웃
};
```

- 반환 직전에 모든 항목을 `JobSchema.parse()`로 검증한다. 검증에 실패한 항목은 버리고 개수를 경고로 남긴다.
- 사이트 원본 응답 → `Job` 변환은 `to<Site>Job(raw)` 같은 **순수 함수**로 분리해서 fixture로 테스트한다.
- 수집기 안에서 다른 수집기를 부르거나, seen.json·메일을 건드리지 않는다.

## 크롤링 예의

- 하루 1회만 실행한다.
- 같은 사이트에 대한 요청 사이에 2~3초 간격을 둔다.
- 사이트당 페이지 수 상한을 둔다 (기본 5페이지).
- 로그인이 필요한 페이지, 개인정보가 있는 페이지는 수집하지 않는다.
- 구현 전에 이용약관과 `robots.txt`를 확인하고, 결과를 해당 사이트 문서에 적는다.
- User-Agent는 일반 브라우저 값을 쓰되, 차단을 우회하려는 시도(프록시 돌리기, 캡차 풀기 등)는 하지 않는다. 막히면 그 사이트는 끄고 사용자에게 알린다.

## 실패 처리

- 네트워크 오류는 1회 재시도. 그래도 실패하면 예외를 던진다 → `index.ts`가 `allSettled`로 받아 경고로 바꾼다.
- 성공했는데 0건이면 정상일 수도 있지만 **경고로 표시**한다. (셀렉터가 깨졌을 가능성)
- 에러 메시지·로그에 API 키나 쿠키가 들어가지 않게 한다.

## 테스트

- `tests/fixtures/<site>.json`(또는 `.html`)에 실제 응답 몇 건을 저장한다. 키·개인정보는 지운다.
- 최소 테스트: fixture → `Job[]` 변환 결과의 개수, id 형식, 필수 필드.
