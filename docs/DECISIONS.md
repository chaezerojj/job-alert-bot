# 결정 기록 (DECISIONS)

> 설계상 중요한 선택을 남긴다. 나중에 "왜 이렇게 했지?"가 궁금할 때 여기서 찾는다.
> 새 결정은 맨 아래에 `D-번호`를 이어서 추가한다. 기존 결정을 바꿀 때는 지우지 말고 "변경됨 → D-xxx"를 적는다.

## 승인된 패키지

아래 목록은 사용자 확인 없이 설치해도 된다. 여기에 없는 패키지는 먼저 물어본다.

| 패키지 | 용도 |
| --- | --- |
| `typescript`, `tsx`, `@types/node` | 언어 · 실행 |
| `zod` | 외부 데이터 검증 |
| `yaml` | profile.yaml 파싱 |
| `dayjs` | 날짜 · KST 타임존 |
| `playwright` | 원티드 렌더링 (내부 JSON으로 충분하면 쓰지 않음) |
| `@anthropic-ai/sdk` | Claude API |
| `resend` | 메일 발송 |
| `@react-email/components`, `react`, `@types/react`, `react-email` | 메일 템플릿 · 미리보기 |
| `vitest` | 테스트 |
| `eslint`, `prettier` 및 TypeScript용 설정 패키지 | 코드 품질 |

## D-001. 서버 없이 GitHub Actions에서 실행한다

- 날짜: 2026-10-13
- 이유: 하루 1회 실행이면 상시 서버가 필요 없다. 비용 0, 관리 부담 0.
- 대가: 실행 시각이 수 분~수십 분 늦을 수 있다. 상태 저장은 저장소 파일로 한다.

## D-002. 고용24와 LinkedIn은 수집하지 않는다

- 날짜: 2026-10-13
- 이유: 사용자 결정. LinkedIn은 약관상 스크래핑 금지이기도 하다.

## D-003. 사람인은 공식 API로 수집한다

- 날짜: 2026-10-13
- 내용: 하루 최대 500회 호출, 1회 최대 110건, 진행 중 공고만 조회 가능.
- 주의: access-key 공개·공유 금지 → 비공개 저장소 + Secrets. 응답에 JD 본문이 없어 매칭은 제목·키워드·직무명 위주.

## D-004. 중복 제거는 data/seen.json + git 커밋으로 한다 (git scraping)

- 날짜: 2026-10-13
- 이유: DB 없이 시작할 수 있다. 실행이 끝나면 Actions가 파일을 저장소에 다시 커밋한다.
- 재검토 시점: 항목이 수천 건을 넘거나 대시보드가 필요해질 때 Supabase로 옮긴다.

## D-005. 매칭은 규칙 필터 → LLM 점수화 2단계로 한다

- 날짜: 2026-10-13
- 이유: 공짜인 규칙 필터로 후보를 30개 안팎으로 줄여 LLM 비용을 낮춘다.
- 안전장치: LLM이 실패하면 규칙 점수로 대체해서 메일은 반드시 보낸다.

## D-006. 메일은 React Email + Resend

- 날짜: 2026-10-13
- 이유: 사용자가 익숙한 React로 메일 템플릿을 만든다.
- 주의: 발신 도메인 인증 전에는 Resend 가입 메일로만 받을 수 있다.
